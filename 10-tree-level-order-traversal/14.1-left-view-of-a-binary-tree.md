# Left View of a Binary Tree

## Problem description

Given the root of a binary tree, return an array containing the values of the nodes in its left view.

The left view is what you see looking at the tree from the left side: for each level, only the **first** node on that level is visible.

## Examples

**Example 1:**

```plaintext
Input: root = [1, 2, 3, 4, 5, 6, 7]

  1 →     1
        /   \
  2 →  2     3
      / \   / \
  4 → 4  5 6   7

Output: [1, 2, 4]
```

**Example 2:**

```plaintext
Input: root = [1, 2, 3, null, null, 4, 5, 6]

  1 →     1
         / \
  2 →   2   3
           / \
  4 →     4   5
         /
  6 →   6

Output: [1, 2, 4, 6]
Explanation: 4 and 6 are visible from the left even though they hang off the right subtree — the left subtree ends at 2.
```

**Example 3:**

```plaintext
Input: root = [8, 4, 9, 3, null, null, 10, 2]

  8 →      8
          / \
  4 →    4   9
        /     \
  3 →  3       10
      /
  2 → 2

Output: [8, 4, 3, 2]
```

## Constraints

- The number of nodes in the tree is in the range `[0, 100]`.
- `-100 <= Node.val <= 100`

## Hints

<details>
<summary>Hint 1</summary>

"Only follow left children" fails on Example 2 — once the left subtree ends, the visible nodes come from the right. Think per level, not per path.

</details>

<details>
<summary>Hint 2</summary>

At the start of each level, the queue holds exactly that level, left to right. Which node is at the front?

</details>

## Solution

### Intuition

The left view is the **first node of every level**. As with the right view, following one side's children doesn't work: when the left subtree is shorter, the leftmost node of a deeper level comes from the right subtree (nodes 4 and 6 in Example 2).

Run the standard level-by-level BFS. At the start of each level the queue holds exactly that level in left-to-right order, so `queue[0]` is the first node on it — record it before processing the level.

```plaintext
level 0   queue: [1]        front → 1
level 1   queue: [2, 3]     front → 2
level 2   queue: [4, 5]     front → 4
level 3   queue: [6]        front → 6

→ [1, 2, 4, 6]
```

### Algorithm

1. If the root is empty, return `[]`.
2. Start a BFS from the root.
3. At the start of each level, append `queue[0].val` to the result.
4. Dequeue the level's `len(queue)` nodes, enqueuing children left then right.

### Complexity analysis

- Time complexity: $O(n)$ — every node is visited once.
- Space complexity: $O(n)$ — the queue can hold a whole level, up to $n/2$ nodes.

```python
from collections import deque
from typing import List, Optional


class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Solution:
    def left_side_view(self, root: Optional[TreeNode]) -> List[int]:
        if not root:
            return []

        result = []
        queue = deque([root])

        while queue:
            result.append(queue[0].val)  # front of the queue is the first node on this level

            for _ in range(len(queue)):
                node = queue.popleft()
                if node.left:
                    queue.append(node.left)
                if node.right:
                    queue.append(node.right)

        return result
```

## Relationship to [Right View of a Binary Tree](./14-right-view-of-a-binary-tree.md)

This is the mirror image of the right view: same traversal, but it reads the front of the queue **before** each level's loop (the first node waiting) instead of the node in hand **after** it (the last one dequeued).
